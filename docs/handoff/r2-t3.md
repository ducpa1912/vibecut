## What was built

1. **One duration source.** Every trim, undo and rebind result lands in one
   `TrimResult` handler in `static/studio/edit/index.js`. That handler updates
   the Edit header, the preview and its scrubber, the playhead, the timeline
   and the story select together. `state.duration` is the only number the
   header, timeline, scrubber and preview read.
2. **Proxy reload by Edit id.** `static/studio/edit/preview.js` observes the
   new Edit id, clears the old frame/proxy, shows **“Rebuilding preview…”** and
   loads the proxy and exact frame for the new id.
3. **Finish waits for a fresh Edit.** `static/studio/finish.js` asks the trim
   route which shapes still match (`aspects[shape].stale`). A stale shape
   disables that row’s queue buttons and “Queue all”, shows an **Edit stale**
   chip and a **Repair** action. A queue `409 edit_stale` is re-read, explained
   and offered the same Repair action.
4. **Both-direction timeline over `pool`.** `static/studio/edit/timeline.js`
   draws the server sentence pool as the axis and the story as a window inside
   it. Start and end handles move outward and inward at sentence bounds.
   Dragging sends `POST …/trim` with `dry_run:true` (debounced, out-of-order
   replies discarded) and shows the live length, collision/limit message and
   receipt (`Moved … · … hidden outside · captions …`). Drop commits the same
   route. `409` reloads the current range/head and explains; `422` keeps the
   old range.
5. **Stories ± uses the same route.** `static/studio/stories.js` no longer
   PATCHes sentence ranges. Its ± buttons call the story trim route with the
   story `revision` and full first/last sentence ids.
6. **Undo trim and receipt.** The Edit screen has an **Undo trim** button and a
   receipt panel. The panel prints the receipt summary, old → new duration and
   how many older renders keep the old cut. Undo posts the receipt token and
   `expected_revision`, then applies the new `TrimResult` (redo is the undo of
   the undo).
7. **Stale-aspect badge and Repair.** Aspect buttons show a red stale dot and
   `aria-label` “…, needs repair”; a **Repair 4:5 / Repair N shapes** button
   calls `POST …/rebind` with the current revision. Finish mirrors the same
   health check.
8. **Hook pin.** A newly added Hook card carries the R2 story pin
   (`pin:"story_start"`; the frozen contract’s `anchor:"story_start"` spelling
   is accepted by T1 and normalized to `pin`). The pin is only written once
   the trim route exists, so the branch cannot send an unknown field to an
   older server.
9. **Hack removal.** `trimOverride`, the timeline’s localStorage job-id lookup
   and the timeline’s direct range PATCH/createEdit fallback are gone. The
   timeline gets the job id from the Edit screen (`ctx.getJobId()` via
   `mount`), passed down as a mount option.
10. **API helpers and cache.** `static/studio/api.js` now owns every trim
    call. Dry runs pass `invalidate:false` so dragging does not empty the read
    cache; committing trim/undo/rebind clears it through the existing write
    path. 409 readers expose `trimErrorCode` / `trimErrorCurrent`.

## APIs and schemas

Consumed exactly as frozen in R2_TRIM_PLAN §2.3:

```text
GET  /api/jobs/{job_id}/clip-sets/{set_id}/stories/{story_id}/trim
POST /api/jobs/{job_id}/clip-sets/{set_id}/stories/{story_id}/trim
     {expected_revision, start_sentence, end_sentence, dry_run?}
POST /api/jobs/{job_id}/clip-sets/{set_id}/stories/{story_id}/trim/undo
     {undo_token, expected_revision}
POST /api/jobs/{job_id}/clip-sets/{set_id}/stories/{story_id}/rebind
     {expected_revision}
```

Helpers in `api.js`:

- `trimPath(jobId, setId, storyId)`
- `getTrimState(jobId, setId, storyId, {fresh})`
- `trimStory(jobId, setId, storyId, {expectedRevision, startSentence, endSentence, dryRun})`
- `undoTrim(jobId, setId, storyId, {undoToken, expectedRevision})`
- `rebindStory(jobId, setId, storyId, {expectedRevision})`
- `trimErrorCode(error)`, `trimErrorCurrent(error)`

`receiptSummary(receipt)` is exported from `stories.js`; it renders
`Moved 3 layers · 1 hidden outside · captions: 12 kept, 2 added`.

## Known gaps

- **No T3 test files.** The ownership list for this track has no `tests/`
  path; T4 owns acceptance and browser tests. The browser run above is
  evidence, not a committed test.
- **Remaining localStorage job-id lookups are unowned.**
  `static/studio/shell.js`, `edit/layers/effects.js`, `edit/layers/clean.js`
  and `edit/layers/audio.js` still read `vibecut.studio.job`. The trim
  timeline no longer does; those files need their owning track.
- **The branch alone has no trim route.** Before T1 merges, `GET …/trim`
  returns 404: the timeline keeps editing usable, disables the handles and
  says trimming needs the latest server. After T1 (and T2 for caption reflow)
  merges, the same code takes the real path.
- **Finish has no preview of its own.** “Preview and Edit hashes agree” is
  enforced as Edit freshness (`aspects[shape].stale`): queue controls are
  disabled for a stale shape and the server still fails closed at POST time.
  The shared rail itself is owned by `shell.js`; Edit has no Finish button to
  disable.
- **No windowed pool.** The timeline shows the full ±90 s pool. On a lone
  story in a long source the story window can be a small fraction of the axis.
  It is correct, just visually tight; a later track can add a paged/windowed
  pool view.
- **Pin spelling.** The frozen text says `anchor:"story_start"`. The Edit
  schema already uses `anchor` for layout, so Studio writes the stored alias
  `pin:"story_start"` (T1 accepts and normalizes both). Layout anchor and pin
  can coexist.
- No founder media was used. No real render, packet or export was run.
