## Built

### 1. Pure trim module (`trim.py`)

No filesystem, job store, requests or ffmpeg.

- `story_revision`, `range_signature`, `bump_revision`: missing revision reads as 0.
- `build_pool`: contiguous source-sentence pool between neighbouring stories, capped at 90 s each side. Current story sentences are always included.
- `validate_range`: contiguous range, 15–90 s (`too_short`, `too_long`, `range_invalid`) and neighbour overlaps (`overlaps_neighbour`).
- `out_to_source` / `source_to_out` / `map_time`: output → source through the old clips, source → output through the new clips. No guessed offset.
- `ripple_graphics`: inside = moved, partly outside = clipped, fully outside = kept with old times and `hidden: true`, pinned = `story_start` / `story_end`. Layers are never deleted.
- `make_receipt` / `new_receipt_id` / `undo_token`: receipt shape and undo token (token is the receipt id; undo writes a new receipt).
- `merge_layer_receipt`: merges per-aspect counts into one receipt.

### 2. Trim routes (`routes_trim.py`)

Prefix: `/api/jobs/{job_id}/clip-sets/{set_id}/stories/{story_id}`.

| Method | Path | Result |
|---|---|---|
| GET | `<prefix>/trim` | `revision`, `story`, `clip_hash`, `pool`, `neighbours`, `aspects`, `limits` |
| POST | `<prefix>/trim` | `TrimResult`; body `expected_revision`, `start_sentence`, `end_sentence`, `dry_run` |
| POST | `<prefix>/trim/undo` | `TrimResult`; body `undo_token`, `expected_revision` |
| POST | `<prefix>/rebind` | `TrimResult`; body `expected_revision` |

The transaction runs under `app.LOCK` and follows §2.4:

1. Load, check revision, check caller aspect pointers.
2. Build the new story through `clipset.apply_edits` with one story patch.
3. Rebuild captions through lazy `caption_reflow.rebuild_for_story`; `ReflowError`, missing T2 and a clip-hash mismatch are `409 caption_rebuild_failed`.
4. Build one new Edit version for every live aspect, with rippled graphics and the new `story_ref` / caption track.
5. Write Edit sidecars, caption sidecar and the receipt under `jobs/<id>/trims/<receipt_id>.json`.
6. One `app.update_job` commit: story, revision, every Edit pointer, `story_captions[key]`.
7. Append Edit history after the commit.
8. Return `TrimResult` and invalidated artifacts. Artifacts are never modified or deleted.

`dry_run` returns the full result with zero writes: no Edit sidecar, no caption save, no receipt, no job commit. `tests/test_trim_routes.py` fails the test if `app.update_job` is called.

Undo restores the receipt's old range, old Edit layers through `edits.restored_edit`, and the old caption pointer, all as new versions. It writes a new receipt and returns a new undo token. It is refused after a later trim (`409 revision_mismatch`) or a later Edit change (`409 edit_changed`).

Rebind repairs every stale aspect Edit (clip-hash mismatch or stale/missing caption track), writes the current-range Edit versions, and returns `stale_aspects: []`.

### 3. Story revision in `patch_clip_set`

- `ClipSetPatchBody` accepts optional `expected_revision`.
- A supplied mismatch is `409 {detail:{code:"revision_mismatch", message, current:{revision}}}`.
- The check is repeated inside `update_job` so the commit is compare-and-swap.
- Every story range change (start/end/dur/sentence order) bumps `revision` by 1. A title-only or identical-range patch keeps the revision.
- Other stories in the same patch keep their revisions.
- New stories start at revision 0.

### 4. Edit schema

`edits.normalize_graphics` now accepts optional:

- `pin`: `"source"` (default when absent), `"story_start"`, `"story_end"`.
- `hidden`: bool.

An Edit without either field hashes exactly as before (tested). `anchor: "story_start"` is accepted as an input alias, because `anchor` already meant the positional overlay anchor (`bottom-center`). The canonical stored story-pin key is `pin`; a positional `anchor` keeps its old meaning.

`compose_render.compile_edit` skips `hidden` graphics. This is the only compose change.

## Schema

### `TrimResult`

```text
{story:{id,start,end,dur,sentence_ids}, revision, duration, clip_hash,
 edits:{aspect: public_edit},
 captions:{track_id, clip_hash, cue_hash, rebuilt},
 receipt:{id, at, kind, job_id, set_id, story_id, revision,
   old:{start_sentence,end_sentence,start,end,dur},
   new:{start_sentence,end_sentence,start,end,dur},
   layers:{moved:[id], clipped:[id], outside:[id], pinned:[id]},
   captions:{kept,moved,dropped,added,manual_kept},
   before:{revision,story,edits,caption_track},
   after:{revision,edits,caption_track},
   invalidated_artifacts:[id]},
 undo_token, invalidated_artifacts:[artifact_id], stale_aspects:[]}
```

`receipt.before` holds the full old story and full old Edit documents for exact undo. Receipts are written under `jobs/<id>/trims/<receipt_id>.json`.

### Errors

- 409 `revision_mismatch`: body carries `current` GET payload.
- 409 `edit_changed`: caller aspect snapshot (optional `aspects` body field) no longer matches, or an Edit is unreadable/missing.
- 409 `caption_rebuild_failed`: lazy import, `ReflowError`, save failure or clip-hash mismatch. Body carries `current`.
- 422 `range_invalid`, `overlaps_neighbour`, `too_short`, `too_long`.

`aspects` on POST trim and rebind is an additive optional guard. It accepts either `{aspect: edit_id}` or the GET shape `{aspect: {edit_id, stale}}`. When omitted, the revision is the only concurrency token. T3 should send the GET `aspects` map to get `edit_changed`.

## Known gaps

- **T2 is not on this branch.** Trim and rebind fail closed with `409 caption_rebuild_failed` until `caption_reflow.py` merges. Unit tests monkeypatch it. There is no fallback caption path by design.
- **Story-pin storage key.** The plan's `anchor: "story_start"` is accepted on input, but storage uses `pin`, because `anchor` is already the positional overlay anchor and changing it would break old Edits, hashes and `compose_render`. T3 should treat `pin` as the story pin and leave positional `anchor` alone.
- **Motion is not rippled.** §2.2 names text, graphic and caption layers. `motion` keeps its output times; clean/reframe/color/audio are source-space or style data and stay unchanged.
- **Legacy `PATCH /clip-sets` still changes ranges.** It bumps revision but does not rebind Edit pointers. T3 must move Stories ± and timeline trims to these routes; T2's render guard closes the plan fallback in the meantime.
- **Rebind always bumps revision and writes a receipt**, even when no aspect was stale. This matches §2.1 listing rebind under revision bumps.
- **No UI/browser run.** T1 is backend only. No server was left running and no founder video was rendered.
- `story_start` pinned layers keep their output offset even if the new story is shorter; the renderer only sees story-length segments. `story_end` pins are clamped.
- Artifact invalidation is a read-only list. No artifact or review link is touched.
