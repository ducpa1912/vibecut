## Summary

- Edit now has a sticky step bar with **← Back to Stories**, a live save state, and **Next: Finish →**. Both buttons, and the existing **All stories** button, flush the autosave first. A failed save keeps the editor open with a visible warning. The rail is unchanged and still navigates.
- Preflight resolves clip-set story ids. `preflight.py` scans the job's clip sets (newest set first when an id repeats), builds the story's plan from its own clips, and returns real findings. A genuine missing story stays a 404 with its server reason; Finish no longer rewrites that as “Render this story first.”
- Queueing is idempotent. `POST /api/story-queues` attaches a story/shape/quality identity to its active queue instead of creating a second queue or a failed “already rendering” row. The queue backend also waits on an active artifact rather than raising 409, and a ready artifact is reused instead of re-rendered.
- Finish has one cross-queue summary: story count, render count, each shape, and running/waiting/done/failed counts. It counts a story/shape once even if the identity appears in more than one queue. Every story row now shows both shapes explicitly (`9:16 · …`, `4:5 · …`) with live queue state.
- Render ETA is hidden until a measured rate exists, never shows 0 while running, and cannot rise inside one render stage. The queue header and the running item use the same estimate chain.
- The frame route accepts `t = duration` and clamps to the last frame. Negative, non-finite, and beyond-one-frame times still return 422.
- Added `StoryRenderBackend.error(item, artifact_id)` for T1's failure-reason hook. It returns the artifact manifest's `error` or `message`, empty when none.

## Known gaps

- **Frame route location:** the frame endpoint is `routes_edits.py:edit_frame`, not `app.py`. The clamp was applied there. `routes_edits.py` was not in the owned list, but no other R3 track claims it. `app.py` has no frame route to edit.
- **Preflight set disambiguation:** the UI sends `set_id` as a query parameter for forward compatibility, but the existing `app.py` preflight route only accepts `story_id` and is outside this track's owned app.py sections. `preflight.py` therefore scans all clip sets and picks the newest set when a story id repeats. A conflict between two sets with the same story id is resolved by newest `created` time, not by the UI's selected set.
- **Single Render duplicate:** `POST /api/jobs/{id}/clip-sets/{set}/stories/{story}/render` still returns 409 for an active duplicate, matching the existing `test_story_render_validation_and_duplicate_active` contract. The idempotent wait/attach path is the queue and `POST /api/story-queues` path.
- **ETA memory is process-local:** `_QUEUE_ETA_STATE` resets on server restart. That only removes the monotonic clamp history; it never invents an estimate.
- **T1 seam:** `StoryRenderBackend.error(item, artifact_id)` is present. It returns the manifest `error` or `message` (and suppresses the generic `Render failed`), empty if the artifact or text is missing. T1's `story_queue.py` hook is not in this branch.
- No changes to rights, watermark, `update_job`, Edit hashing, or plan-path fallback rules.
