# Wave 2 T3 — TTS, engine removal and packs

**Branch:** `rv/w2-t3-tts-packs`  
**Base:** `wave-2-base` (`eb13302`)  
**Baseline:** 1004 tests. **This branch:** 1032 tests.  
**Scope:** T3 only. No `static/studio/**` ownership and no Studio files touched.

## What was built

### TTS final set

`tts.py` now exposes the five final voice engines:

- MiniMax Speech 2.8 (`minimax`)
- ElevenLabs (`elevenlabs`)
- OpenRouter (`openrouter`, synthesised as Fish S2.1 or Gemini Flash-Lite)
- Kokoro (`kokoro`)
- Apple `say` (`say`)

Removed from the registry, `list_voices`, route parsing and `synthesize_line`:
Piper, OpenAI TTS, Groq Orpheus, Deepgram Aura and Cartesia.

New story-level API:

- `line_cache_key(engine, model, voice, text, rate, language)` — SHA-256 over
  canonical JSON. Every field that changes audio is in the key.
- `line_cache_path(...)` — per-sentence `.flac` under `data/cache/voice`.
- `synthesize_story(lines, engine=..., voice=..., language=..., routes=...)` —
  one engine and one voice for the whole story. If any sentence fails, the
  whole story restarts on the next configured engine. A failed attempt never
  contributes a clip to the result.
- `voice_engine_status()` — final-only readiness map for the next owner of
  `/api/audio/engines`.
- `voice_sample(..., model=..., language=...)` now uses the same six-field
  cache key.

`ENGINES` is the five-name product set; `SYNTHESIZERS` keeps the internal
`fish`/`gemini` split that the OpenRouter adapter needs.

### Packs

New `packs.py`:

- built-in manifest for **Speech Pack** (~1.9 GB), **Voice Pack** (~0.8 GB) and
  **Separation Pack** (~0.8 GB), plus `VIBECUT_PACK_MANIFEST` file override;
- manifest validation (schema, unique ids, sizes, SHA-256 shape);
- streaming SHA-256 verification before extraction;
- install from a local archive or an HTTP(S) pack URL;
- zip and tar extraction with path-traversal, symlink, hardlink and device
  rejection;
- install under `~/Library/Application Support/VibeCut/packs/` (override with
  `VIBECUT_PACKS_DIR`);
- atomic replace of a previous install; a failed verify leaves the old install
  untouched;
- `remove_pack` refuses symlinked pack directories;
- `status`, `list_packs`, `human_size`.

### Settings migration

`settings_store.load_settings()` now migrates the stored settings document and
writes the migrated copy back once. Trigger is a real value change, so the
founder's old `data/settings.json` is rewritten on first load and not on every
later load.

| Old value | New value |
|---|---|
| TTS `piper` | `kokoro` |
| TTS `openai`, `groq`, `deepgram`, `cartesia` | `minimax` |
| Local TTS route model `piper` | `kokoro` |
| Text provider `local-mlx` | route dropped |
| Text provider `ollama` | route dropped |
| Workflow with zero routes after cleanup | built-in default list |
| STT workflow provider `auto` | `apple` / on-device |
| STT workflow provider `openai` | `groq` / `whisper-large-v3-turbo` |
| STT workflow model `whisper-small-mlx` or `whisper-1` | `whisper-large-v3-turbo` |

Stale keys (`openai`, `cartesia`) are hidden from the admin key list and are
deleted from `secrets.json` only after explicit confirmation through
`POST /_ductator/api/keys/confirm-removals` with `{"confirm": true}`.
Environment-managed stale keys cannot be deleted by the app and stay listed.

### Admin and Classic UI

- `workflow_config.TEXT_PROVIDERS` is `opencode-go`, `openrouter`;
  `_TEXT_ROUTES` no longer contains `local-mlx`.
- `workflow_config.TTS_PROVIDERS` is `minimax`, `openrouter`, `local`,
  `elevenlabs`; default TTS routes no longer contain Piper.
- `workflow_config.STT_PROVIDERS` is `apple`, `whisper`, `groq`, `deepgram`;
  default STT route is Apple → Whisper turbo.
- Admin workflow provider dropdowns come from `WORKFLOW_PROVIDERS`, so removed
  providers are not offered. `/_ductator/api/catalog` rejects removed providers
  and filters `local:piper`; `_safe_workflow_payload` also rejects Piper.
- Admin masked-key list hides `openai` and `cartesia`; a "Removed engine keys"
  card offers confirmation.
- Classic `static/app.js`: voice option filter is `say`, `kokoro`, `minimax`,
  `fish`, `gemini`, `elevenlabs`; music options are library, MiniMax, Lyria;
  Argos/Marian/Ollama/Piper/OpenAI/Groq/Deepgram/Cartesia/Stable Audio/MusicGen
  labels are gone.
- `README.md` now documents the final STT/TTS/music/text engines, the three
  optional packs, the final provider catalog, environment variables, the
  migration and the removed keys. Removed provider/env references are gone
  except where the text explicitly records their removal.

## Known gaps / blocked work

These need files outside T3's ownership. Per the hard rule I did not edit them.

1. **`/api/audio/engines` still advertises removed engines.**
   `audio.py:381 engine_status()` hard-codes `piper`, `openai`, `groq`,
   `deepgram` and `cartesia`, and `app.py:6274` returns it unchanged. A
   follow-up must delegate `voices` to `tts.voice_engine_status()`, drop
   `piper_bin`, and update `tests/test_vibecut.py::test_engine_status_shape`
   (which currently asserts the old set). This is the one explicit requirement
   of this track that cannot be completed inside the ownership list.
2. **Live voice-over still falls back per sentence.**
   `audio.build_bed` (`audio.py` around the TTS section) tries each route for
   each line, so a mid-story failure can mix engines. It must call
   `tts.synthesize_story(...)` once per story. `synthesize_story` is tested and
   ready; the wiring is in the unowned `audio.py`.
3. **Legacy TTS adapters remain.** `tts.py` still defines `_piper_voice`,
   `_openai_voice`, `_groq_voice`, `_deepgram_voice` and `_cartesia_voice`
   because `audio.py:3360` re-exports those names and `tests/test_vibecut.py`
   exercises them. They are unreachable from `synthesize_line`, `list_voices`
   and route parsing. Delete them after the `audio.py` re-export cleanup.
4. **`admin/catalog.py` still stores old model entries** (`local:piper`,
   `openai`, `cartesia`, `auto`, `local-mlx`, `ollama`). `admin/routes.py`
   filters providers and models before the picker sees them, so the UI is
   clean, but the static data needs an owner pass.
5. **`app.py` live-test candidate lists still name Piper.**
   `app.py` uses `("minimax", "fish", "gemini", "kokoro", "piper", "say")` for
   the TTS live test. With a Piper install present it can select Piper and then
   report "No voices" because `tts.list_voices("piper")` is empty. Fix with the
   same engine-status cleanup.
6. **Top-level Setup STT values are not migrated.** `settings["stt"]` can still
   read `auto` / `openai` / `whisper-small-mlx`. The workflow routes (the path
   the pipeline uses) are final. Top-level migration was left alone because
   unowned `tests/test_vibecut.py` asserts the old saved values
   (`stt.provider == "auto"`, `stt.model == "mlx-community/whisper-small-mlx"`).
7. **Packs are not wired into engine paths.** `packs.py` installs and verifies
   under Application Support, but `audio.py` still reads Kokoro from
   `data/models/kokoro` and Whisper from `mlx_whisper`/the environment. Wave 4
   Setup owns the install UI; the engine-path handoff is in `audio.py`.
8. **Built-in pack URLs and SHA-256 pins are blank** until the release host is
   created. `VIBECUT_PACK_MANIFEST` supplies real values; install refuses a
   manifest entry without a pin.
9. **Classic has three legacy `cc0` fallbacks** in `static/app.js` outside the
   label/option sections. They coerce old saved jobs toward the library and do
   not offer `cc0`; ports left untouched to respect the "label maps and option
   lists only" boundary.
10. **Voice catalogue 24 h cache and 5-second preview UI** from REVAMP §7.3 are
    not in this track; the engine/voice list APIs are ready.
11. **Setup drawer confirmation UI** for stale keys lives in the admin console
    (`static/admin.js`). `static/creator.js` is unowned, so the Classic Setup
    drawer does not show the prompt yet.
