## What was built

1. **`_segment` accepts compiled filters.**
   - New `pre_filters` / `post_filters` arguments. Pre-filters run before
     crop/scale (clean layers); post-filters run after scale/fps/format
     (motion, perspective, colour); fades stay last.
   - `_segment_cache_key` adds SHA-1 hashes of both filter lists. Legacy keys
     are unchanged when both lists are empty, so existing segment caches stay
     valid.
   - `_crop_filter` also accepts an exact source-pixel `{x,y,w,h}` crop, which
     is what `compose_render` emits.
2. **Motion is subpixel on the Edit render path.**
   - `compose_render.compile_edit(..., motion_engine=...)` adds a
     `perspective` engine used by Edit renders. Corners are evaluated per
     frame (`eval=frame`, cubic interpolation) so push/punch/snap/shake no
     longer inherit `zoompan`'s whole-pixel crop-origin rounding.
   - Zoom keyframes are compiled through the shared
     `compose_render.path_expression` (moved from `render.py`); the frame
     numbering variant substitutes `on/30` for `t`.
   - `render.py` still re-exports `_path_expression` / `_path_value` names.
   - The legacy plan path keeps `motion_engine="zoompan"` by default, so all
     Wave 1 golden strings and existing renders are unchanged.
   - Measured on a 2 s dot fixture (`push`, amount 0.06), per-frame centroid
     step:

     | size | engine | step std | max step |
     |---|---|---|---|
     | 1080x1920 | zoompan | 0.906 px | 1.618 px |
     | 1080x1920 | perspective | 0.132 px | 0.471 px |
     | 540x960 | zoompan | 0.666 px | 1.721 px |
     | 540x960 | perspective | 0.076 px | 0.299 px |

     `tests/test_render_layers.py::test_perspective_motion_is_smoother_than_zoompan`
     asserts the perspective std is below half the zoompan std.
3. **`_burn_captions` → `_burn_layers`.**
   - `_burn_layers` takes compiled overlay layers, rasterizes each one, and
     burns them in one encode. An empty layer list starts no process.
   - Static layers (text, captions, underline, arrow, circle) are one PNG.
     Animated layers (`progress_bar`) are PNG sequences at the output fps.
   - Rasterized frames are cached under `data/cache/layers/<layer-hash>/...`.
     The hash covers text, style, rect, opacity, canvas, fps and frame count.
   - `_burn_frame` reuses the same rasterizer for one frame, which is the
     frame endpoint's path.
   - Legacy `_burn_captions` is kept for plans without an Edit so Wave 1
     caption rendering stays byte-identical.
4. **Frame endpoint.**
   - `GET /api/jobs/{job_id}/edits/{edit_id}/frame?t=<seconds>&quality=draft`
     returns `image/jpeg`.
   - It compiles the Edit at the requested canvas (`draft` 540-wide, `final`
     1080-wide), renders the segment containing `t` through `_segment` (same
     cache and filter chain as the final render), extracts that exact frame,
     and burns the active layers through `_burn_frame`.
   - `quality` accepts `draft` or `final`; anything else is 422.
   - JPEGs are cached at `data/cache/frames/<key>.jpg` keyed by edit hash,
     frame number, quality, source fingerprint, encoder and layer hashes.
5. **Story proxy.**
   - `GET /api/jobs/{job_id}/edits/{edit_id}/proxy` returns `video/mp4`.
   - Built from the story clips with `_segment` → `_concat_video` →
     `_audio_track` → `_mux`, at 540 wide (540x960 for 9:16, 540x676 for
     4:5), then cached at
     `jobs/<job>/proxies/<clip-hash>_<aspect>_540x960.mp4`.
   - The same path is returned on later requests without rebuilding.
6. **Tests.**
   - Golden strings for perspective push/punch/snap/shake, legacy zoompan,
     layer raster modes/hashes, filter-cache keys and burn graph shape.
   - Route tests: 404 unknown edit, 409 stale story (clip hash), 422 bad
     `t` / quality, JPEG and MP4 content types, proxy reuse.
   - Real ffmpeg: 2 s synthetic clip with plate + warm_film colour +
     punch-in + text + progress bar renders at 1080x1920; the frame endpoint
     at `quality=final` matches the final frame at SSIM ≥ 0.98 (the test
     computes the score with a 7x7-window SSIM helper).
   - Real ffmpeg: proxy is probed at 540x960 with audio, and a second request
     returns identical bytes without touching the cache mtime.

## Endpoints and schemas

| Method | Path | Response |
|---|---|---|
| `GET` | `/api/jobs/{job_id}/edits/{edit_id}/frame?t=<seconds>&quality=draft\|final` | `image/jpeg` (draft 540-wide, final 1080-wide) |
| `GET` | `/api/jobs/{job_id}/edits/{edit_id}/proxy` | `video/mp4` (540-wide story range) |

Status contract for `frame`:

- `404` unknown job or unknown Edit id.
- `409` stale story: clip-set source fingerprint changed, or the story clip
  snapshot no longer matches `edit.story_ref.clip_hash`.
- `422` missing/non-finite/negative/out-of-range `t`, or unknown `quality`.

`proxy` uses the same `404` / `409` checks before building.

`render.render_reel` gained `edit=` and `compiled_edit=` keywords. When
`edit` is set, it compiles with `size=(out_w, out_h)` and
`motion_engine="perspective"`, overrides `render_clips` with the compiled
frame-rounded segments, and burns the compiled overlay list through
`_burn_layers`. The returned dict adds `layers`, `layer_count` and
`edit_hash`.

## Known gaps

- **App wiring is not in this track.** `render_reel(edit=...)` is the hook;
  the Finish/artifact path still calls `render_reel` without an Edit. Wave 4
  T1 must pass `edit`/`compiled_edit` and extend `artifacts.py` identity.
- **`reframe.crop_path_ref` is still unresolved.** The compiler returns the
  reference and the renderer can consume `crop_path` points, but no code
  loads the referenced path into `compile_edit`.
- **Animated layers are limited to `progress_bar`.** Word-pop, type-on,
  arrow draw-on and sticker animation belong to Wave 3 compose/UI work.
  Sticker layers with an `asset` but no `asset_path` are skipped.
- **Frame endpoint cold cost.** The first frame for a segment renders the
  whole segment (draft, cached) before extracting one frame. JPEG and segment
  caches make later frames cheap. Wave 5 performance work can add a
  frame-only path.
- **Proxy has no Edit look.** It is a plain 540-wide story-range proxy for
  scrubbing, not a preview of clean/color/text/caption layers.
- **Legacy clip sets without source fingerprints** can serve a stale proxy if
  the source file changed but the clip windows did not; `_check_fresh` only
  warns for those sets.
- **Motion runs on the output canvas.** Perspective is cubic and about 5x the
  cost of zoompan for motion segments. It is enabled only for Edit renders;
  legacy plans keep zoompan.
- **Frame cache versioning.** Cache keys cover the layer skin version and
  source fingerprint, but not the Pillow/ffmpeg build. A toolchain change
  should bump `LAYER_CACHE_VERSION`/clear `data/cache`.
- **No Studio UI ownership for T1.** No `static/studio/**` files changed.
