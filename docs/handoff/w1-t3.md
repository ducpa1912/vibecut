## What was built

Source Check is a new, advisory pass that runs after analysis and before
Stories. It reads existing analysis evidence plus a 0.5 fps OCR sample, groups
on-screen text into persistent tracklets, and returns a `SourceReport` with a
recommendation, Clean pre-fill, policy gates and warnings.

### 1. OCR line boxes are kept

`pipeline._apply_scene_read` now keeps one entry per accepted Vision line:

```json
"ocr_boxes": [
  {
    "text": "burned caption",
    "confidence": 0.91,
    "box": {"x": 0.1, "y": 0.78, "w": 0.8, "h": 0.07}
  }
]
```

- `box` is source-normalized, top-left origin, 0–1.
- `scene["ocr"]` keeps the previous joined string, so existing scoring,
  hook text and UI code are unchanged.
- `scene["ocr_confidence"]` is the mean accepted line confidence.
- `pipeline.ocr_lines(record)` is the shared filter (the old 0.18 confidence
  and 2-character rules). It no longer drops the geometry.
- Lines without usable geometry still contribute text, so a legacy record can
  never look text-free because its boxes were missing.

### 2. 0.5 fps sampled text pass

`pipeline.extract_text_frames` runs one ffmpeg pass at `fps=0.5` (one frame
every two seconds), scaled to 960 px wide. `pipeline.read_text_samples` OCRs
those frames with the existing Vision helper and returns:

```json
{
  "frames": [
    {"index": 0, "file": "000001.jpg", "t": 0.0, "start": 0.0, "end": 2.0,
     "text": [{"text": "...", "confidence": 0.9, "box": {"x": 0, "y": 0, "w": 1, "h": 1}}]}
  ],
  "vision": true,
  "fps": 0.5,
  "duration": 5400.0
}
```

- Long sources lower the cadence so the pass never exceeds 3,600 frames
  (`CHECK_SAMPLE_MAX_FRAMES`).
- Frames are written under `jobs/<id>/check/frames/` and deleted afterwards.
  Set `VIBECUT_KEEP_CHECK_FRAMES=1` to keep them for debugging.
- `vision` distinguishes "these frames have no text" from "this machine
  cannot read text". That distinction drives `text.confirmed`.

### 3. `detect.py` (new)

Pure detection and report code. It makes no ffmpeg calls, no Vision calls, no
network calls and needs no model packs.

- `merge_lines` joins OCR lines from one frame into blocks (two-line captions
  become one box).
- `cluster_observations` groups blocks by geometry and time (IoU, centre
  distance, width/height ratio, 4.5 s gap).
- `classify` applies rule-based kinds:
  - `watermark`: small corner platform mark, or literal "watermark"/"©".
  - `handle_or_logo`: small corner @handle, URL/CTA, or persistent corner logo.
  - `subtitle`: lower-band (or mid-frame wide) text with a 1–5 s-ish change
    rate, plus static wide captions.
  - `title`: large or long-lived text.
  - `lower_third`: static lower-band text, narrower than a caption.
  - `credit`: small bottom text.
- `speech_signal`: coverage from scene speech ranges (analysis transcript).
- `music_from_wav`: energy stability + spectral flatness over non-speech
  windows, 200 ms windows, 16 kHz mono wav.
- `music_from_scenes`: fallback from scene level/silence values when the wav
  cannot be read.
- `faces_signal`: coverage, count, merged ranges, up to 20 sample boxes.
- `quality_signal`: resolution, bitrate, bits-per-pixel, orientation, issues.
- `build_report`: assembles the `SourceReport`.
- `cleanup_block_reason(kind, attested)` is exported for Wave 3 Clean code.
  It keys on the detected kind, not a user label.
- `write_report` / `load_report` store the report atomically at
  `jobs/<id>/check/source_report.json`.
- `run_check` orchestrates sampling, audio, report build and storage with
  injected `sampler` / `audio_extractor` callables.

### 4. `routes_check.py` (new)

`POST/GET /api/jobs/{id}/check`, registered in `app.py` with an import and an
`include_router` line only. The pass runs on its own single-worker
`job_queue.Scheduler` (keyed by job id), so it does not block analysis or
render.

| Method | Path | Result |
|---|---|---|
| `POST` | `/api/jobs/{id}/check` | `200` + ready `SourceReport`; `202` + incomplete envelope while queued/running; `409` analysis not ready; `404` unknown job; `422` bad body; `500` if an inline worker fails |
| `GET` | `/api/jobs/{id}/check` | `200` + report (or failed envelope); `202` while running; `404` before the first run |

Request body (optional, `extra="forbid"`):

```json
{
  "force": false,
  "attestation": true,
  "sample_text": true,
  "fps": 0.5
}
```

- `fps` is bounded to 0.1–2.0. The Check default is 0.5.
- `attestation` accepts a bool or the same truthy strings as the cleanup
  prototype.
- `force` re-runs a finished check. A `POST` while a task is genuinely active
  returns `202` and does not start a second pass.
- A stale `running` record after a restart (no live scheduler task) is
  replaced by the next `POST`.
- Job summary: `job["check"] = {status, progress, message, error,
  recommendation, tracklet_count, duration_s, report, task_id, attestation,
  updated}`.

### `SourceReport` schema

```json
{
  "schema": 1,
  "status": "ready",
  "complete": true,
  "job_id": "…",
  "created": 0.0,
  "source": {"name", "duration", "width", "height", "fps", "has_audio"},
  "text": {"present", "confirmed", "sampled_fps", "frames_read",
           "ocr_available", "tracklets", "coverage", "approximate"},
  "tracklets": [{
    "id": "trk_0001",
    "kind": "subtitle",
    "box": {"x", "y", "w", "h"},
    "ranges": [{"start", "end"}],
    "text_sample": "…",
    "confidence": 0.91,
    "samples": 5,
    "duration": 10.0,
    "approximate": false
  }],
  "audio": {"available", "has_audio", "speech_seconds", "speech_ratio",
            "speech_ranges", "transcript",
            "music": {"available", "present", "score", "method", "…"}},
  "faces": {"present", "count", "coverage", "ranges", "boxes"},
  "quality": {"width", "height", "fps", "duration", "orientation",
              "bitrate_mbps", "bits_per_pixel", "issues"},
  "recommendation": "clean_then_compose | compose | music_first",
  "recommendation_reasons": ["…"],
  "clean_prefill": [{"tracklet_id", "kind", "box", "ranges", "action",
                     "enabled", "confidence", "reason", "blocked"}],
  "policy": {"clean_allowed", "rights_attested", "attestation_source",
             "watermark_refused", "handle_or_logo_ids",
             "requires_attestation", "refusals"},
  "rights": {"attested", "source"},
  "warnings": [{"code", "severity", "message", "tracklet_ids"}],
  "engine": {"vision", "sampled_pass", "sample_fps", "sampler_error",
             "audio_error", "music"},
  "timings": {"total"},
  "error": null
}
```

Tracklet `box` is source-normalized 0–1. `ranges` are absolute source times.
Extra fields (`samples`, `duration`, `approximate`) are additive.

### Policy behaviour

- A `watermark` tracklet is always refused. `clean_prefill` emits
  `action: "refused"`, `enabled: false`, `blocked: "watermark"` and the warning
  text: **"Use your original file — it has no watermark."**
  `policy.watermark_refused` and `policy.refusals` list the ids.
- `handle_or_logo` needs the own-footage attestation. It is always off by
  default; with attestation it becomes `crop_guard` at an edge or `blur`
  elsewhere, still `enabled: false`.
- Without attestation, `policy.clean_allowed` is false and every Clean entry is
  blocked (`rights_not_attested`).
- `text.confirmed` is true only when the full sampled pass ran, read at least
  one frame and Vision was available. Scene OCR can find text but cannot
  confirm its absence. An unconfirmed report gets `text_unconfirmed` and never
  says the source is clean.
- Recommendation: `clean_then_compose` when cleanable text exists (handles
  count only when attested); `music_first` when there is no audio or speech is
  ≤ 5%; otherwise `compose`.
- `clean_prefill`: subtitles in the caption band → `plate`; mid-frame
  subtitles → `blur` + `mid_frame_text` warning; titles → `mask`; credits and
  lower thirds → `blur`.

## Tests

`tests/test_detect.py` covers:

- OCR box retention, filtering, normalization, `read_text=False`.
- Sampled pass cadence, max-frame capping, Vision-unavailable signal, frame
  mapping and cleanup.
- Line merging, tracklet clustering, ranges, deterministic ids, contract
  fields.
- All six kinds, including watermark vs large platform title.
- Speech, faces, quality, music from wav (tone/silence/speech-excluded) and
  the scene fallback.
- Recommendation paths, unconfirmed text, watermark refusal, handle
  attestation, rights lock, Clean pre-fill actions, warnings.
- Report write/load round-trip and state envelopes.
- `run_check` with fakes, sampler failure, sampling disabled, audio path.
- Routes: happy path, caching, force, unready job, unknown job, failed worker,
  stale running recovery, body validation.

No test hits the network, ffmpeg, Vision, a model pack or a real source file.

## Known gaps

- **No Studio Check UI.** That is T4 / Wave 3 (`static/studio/check.js`). This
  track exposes the API and report only.
- **Clean pre-fill is advisory.** It does not create Clean layers. Wave 3 T2
  owns `cleanup.py`; it should call `detect.cleanup_block_reason` with the
  detected kind.
- **Kind rules are heuristics.** They are tuned on synthetic fixtures and unit
  tests, not the founder's 30-source corpus. The acceptance gates
  (`subtitle` vs `title` ≥ 90%, 100% watermark refusal, zero false clean) still
  need the real corpus.
- **Sampled-pass timestamps are approximate.** Frames come from one ffmpeg
  `fps` filter pass; each sample is assigned `index / cadence` and a
  `1 / cadence` window. A frame is a snapshot, not proof of the whole window.
- **Audio pass re-extracts a full 16 kHz wav.** `pipeline.extract_audio` writes
  `jobs/<id>/audio.wav`; `detect.run_check` deletes it after the music estimate.
  `music_from_wav` reads the whole file into memory (~345 MB for 90 min). The
  scene-level fallback is used when audio extraction or the wav read fails.
- **The music estimate is conservative and not a classifier.** It reports
  energy stability, spectral flatness and a score. It does not identify genre
  or separate music from speech when no transcript exists.
- **Attestation is stored in the report and `job["check"]["attestation"]`,**
  not in a job-level `rights` object. Wave 3's import-time rights attestation
  can become the canonical field; `detect` already reads `job["rights"]`,
  `job["attestation"]` and `job["options"]["attestation"]` when present.
- **No cancellation.** There is no `POST …/check/cancel`; a long pass runs to
  completion. The scheduler is single-worker and keyed per job.
- **A stale `running` state is only replaced by a new `POST`.** `GET` keeps
  returning `202` until the client retries. This avoids silently starting work
  from a read.
- **`job` responses do not include the check summary.** Adding it to
  `public_job` would require an `app.py` change beyond the allowed import and
  include lines. Clients use `GET /api/jobs/{id}/check`.
- **Vision helper mode.** The sampled pass uses the existing `.accurate`
  recognition level because `tools/vision_probe.swift` is not owned by T3. The
  plan's "fast recognition" option needs a helper change in a later wave.
- **Classic scripts unchanged.** `node --check` passes; no `static/` files were
  edited.
