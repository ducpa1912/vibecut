## Built

### #18 — Final render of a 26 s story from 1440p AV1

The decode path was not the 2 min 50 s bottleneck. The caption burn was.

`_burn_captions` and `_burn_layers` gave every caption cue its own looped PNG input and its own `overlay` filter. An overlay chain composites every input into every frame, so the cost grows superlinearly with the cue count. A clean 26 s master with 60 cue overlays took **112.7 s** on this M1; 30 overlays took 21.7 s and 2 overlays 4.0 s. That matches the founder's observation once the story has roughly 60–80 cues.

Changes:

- **One timed caption track.** Static caption cues are collapsed into one concat-demuxer PNG track plus one `overlay`. A transparent PNG fills gaps, so timing and z position are unchanged. `CAPTION_TRACK_MIN = 8`; shorter stories keep the old chain. Contiguous runs are collapsed separately when a graphic sits between caption groups. Overlapping cues fall back to the per-cue chain because a single track cannot reproduce a stack.
- **Decode args.** AV1 uses `-c:v libdav1d` explicitly. The Homebrew ffmpeg 9.0.2 build has no `av1_videotoolbox` decoder, and `-hwaccel videotoolbox` with AV1 fails with `Function not implemented` on this M1. `VIBECUT_DECODER=videotoolbox|software` is the opt-in for machines whose ffmpeg has AV1 hardware decode.
- **Thread budget.** The beat pool gives each dav1d process `cpu_count / workers` threads instead of letting four full thread sets fight over eight cores.
- **Scale order.** For sources above 30 fps, `fps=30` now runs before `scale` in `_crop_filter`. A 60 fps source no longer scales frames that are immediately dropped. Sources at 30 fps or below keep the old `scale → fps` order.
- **Seek stays before input.** `-ss` is already before `-i`. Output seek measured 7.53 s CPU / 2.88 s wall for a 6 s window versus 4.32 s / 1.68 s for input seek, so the fast path is correct and was left alone.

### #21 — Shared per-job Studio read cache

`static/studio/api.js` now owns one read cache for job-scoped JSON:

- job (`GET /api/jobs/{id}`), clip-sets, Check report, edits list;
- plus the other job-scoped reads the steps repeat: packets, preflight, current Edit, caption track;
- never `/status`, `/artifacts` (Finish polls artifacts every 2.4 s), frame/proxy/thumb/poster/reel/download/media URLs.

Invalidation:

- every non-GET through `request()` clears the cache in a `finally`, so a failed write also drops stale reads;
- `uploadVideo()` clears it on success;
- a fresh job read whose `updated`/`updated_at` stamp changed drops that job's derived reads but keeps the new job;
- the shell watcher reads the full job with `fresh: true` every 150 s and compares the stamp. The status poll stays at 15 s, so the five-minute cost is 20 status reads + 2 job reads.

Concurrent reads of one path share one in-flight request. Cached values are cloned, so a panel cannot mutate another panel's copy. `readCacheStats()` exposes hits, misses, coalesced reads, writes and size.

Request budget for a five-minute idle session that opens every step twice:

| Source | Requests |
|---|---|
| status watcher, 15 s | 20 |
| fresh job stamp watcher, 150 s | 2 |
| first unique per-job reads (job, sets, check, edits, packets, preflight, current Edit) | 7 |
| artifacts, two Finish mounts | 2 |
| story queues, two Finish mounts | 2 |
| shares, two Finish mounts | 2 |
| recent videos, two Import mounts | 2 |
| boot status | 1 |
| **Total** | **38** |

Stories only polls `/status` while a video is still reading, so a ready session adds nothing there.

## Known gaps

- AV1 VideoToolbox is not auto-detected. It is only reachable through `VIBECUT_DECODER=videotoolbox` on M3+ hardware and an ffmpeg build with AV1 hwaccel. Forcing it on this M1 fails, as expected.
- Overlapping caption cues fall back to the old per-cue overlay chain. Normal cue tracks do not overlap; a hand-built overlapping track stays correct but slow.
- The timed track handles static caption layers. A `progress_bar` sequence still gets its own input per layer, which is fine at the usual one or two layers.
- External writes are picked up by the 150 s job-stamp read. Writes through `api.js` invalidate immediately. `/status` is always fresh.
- `/artifacts` is not cached because Finish polls it every 2.4 s during active renders. Story queues and shares are global reads and stay uncached.
- `/api/jobs/{id}/status` does not carry `updated`; the shell reads the full job to see the stamp. If T1 later adds the stamp to status, the 150 s read can be removed.
- The 60 fps improvement (fps before scale) is unit-tested on the filter string, not profiled on a 60 fps source. The 26 s profile source is 30 fps.
- The profile host was shared with the other R1 agents. The 15.29 s wall has margin; the CPU total and stage split are the reproducible numbers.
