## Built scope

### 1. `caption_reflow.py`

```python
rebuild_for_story(
    job_id, job, set_id, old_story, new_story, old_track_id,
    *, job_dir=None,
) -> ReflowResult
```

- The old track is loaded, never mutated, and never saved by the rebuild.
- Every old cue maps old output time -> source time through the old clips,
  then source time -> new output time through the new clips.
- Outcomes:
  - exact same output times -> `kept`;
  - shifted or clipped to the new edge -> `moved`, text kept verbatim;
  - no overlap with the new range -> `dropped`;
  - source spans the old story never covered -> fresh cues from the
    transcript, using the old track's style and chunking -> `added`;
  - surviving cues whose text is no longer a substring of the transcript
    excerpt for their source span -> `manual_kept` (manual fixes are never
    retranscribed).
- `ReflowResult`:
  - `track` — `caption_engine.CaptionTrack`, not saved;
  - `counts` — `{kept, moved, dropped, added, manual_kept}`;
  - `old_track_id`;
  - `track_id` and one property per count;
  - `save(job_dir) -> track_id` writes the immutable sidecar and returns the
    new id.
- The new track's `clip_hash` equals
  `caption_engine.clip_hash(new_story["clips"])`, i.e. the new story has.
- `parent_id` and `version + 1` continue the old track's chain. `style`,
  `style_id`, `transcript_id`, `source` and warnings carry over.
- Raises `caption_reflow.ReflowError` when the new story has no clips, the old
  track id cannot be read, or added material exists but the job has no
  transcript. T1 maps this to 409 `caption_rebuild_failed`.

### 2. Cached track rejection

- `app.default_story_caption_track`: a cached track is returned only when its
  `clip_hash` is the story's current hash (raw story clips or the
  frame-rounded render cut). A stale track is rebuilt from the current plan.
  Legacy tracks with an empty `clip_hash` are accepted because they predate
  clip identity and cannot be verified.
- `app._edit_caption_track`: rejects a non-empty track `clip_hash` that is not
  the Edit's story hash or the current frame-rounded story hash, with 409
  "The caption track does not match this story. Rebuild the track."
  A deleted track still renders no captions (existing behaviour).

### 3. Fail-closed render identity

`app._story_edit_for_render`:

- no pointer -> `None`, legacy plan path unchanged;
- pointer + missing/unreadable/aspect-mismatched Edit -> 409;
- pointer + Edit whose `story_ref.clip_hash` differs from the story -> 409.

Response shape (FastAPI wraps `detail`):

```json
{"detail": {"code": "edit_stale",
            "message": "This story changed after its Edit was made. Open it in Edit and press Repair."}}
```

No plan fallback exists while a pointer is present.

Call sites:

- `POST /clip-sets/{set_id}/stories/{story_id}/render` — synchronous 409.
- `POST /api/story-queues` (Finish queue) — pre-validates every item before
  the queue is created, so the request itself returns 409 instead of a queued
  item that fails later.
- `packet.build_packet` — 409 `PacketError("edit_stale")` before any packet
  file is written. `packet.py` checks the request story and every story
  derived from the selected artifacts. A plan-only job with no clip set is
  skipped because there is no story to compare.

### 4. `routes_edits._payload`

Adds `stale: bool` to the top level and inside `edit`. It is true when the
Edit's story is gone or its clip hash no longer matches the Edit's
`story_ref.clip_hash`.

### 5. One track for every surface

- Burned cues come from `_edit_caption_track` -> render `caption_cues`.
- Artifact SRT/VTT are written from those same cues.
- Packet reads the artifact `captions.srt` (`_captions_from_record`).
- `caption_reflow` only changes where the track comes from; it does not create
  a second cue path.

## Known gaps

1. **Render may re-chunk a reflowed track when frame rounding changes the clip
   hash.** `_queue_render_locked_impl` sees a track whose `clip_hash` is the
   raw story hash, calls `caption_engine.build_track(..., style)` for the
   frame-rounded cut, and that rebuild re-reads the transcript. The burned
   cues and SRT stay from one track, but a manual caption fix can be lost on
   the render path when `prepare_render` changes a clip end. The fixture clips
   are frame-aligned, so the tests do not hit it. The correct fix is in
   `_queue_render` (not owned by T2): treat an explicitly supplied story
   track whose hash is the story hash as authoritative instead of rebuilding.
2. **Legacy empty `clip_hash`.** Migration tracks have no clip hash, so they
   cannot be checked. They are accepted on the Classic/migration path.
   Rejecting them would break every migrated job.
3. **Packet strictness.** Any stale pointer for the packet's story blocks the
   packet, even if the packet only contains the other aspect. This is the
   fail-closed reading of §2.6; a per-aspect packet check is a follow-up.
4. **Plan-only packets** have no clip set to compare, so the story hash check
   is skipped there.
5. **Out-of-ownership test update.** `tests/test_story_edit_render.py` had to
   change because two tests asserted the old "stale Edit falls back to the
   plan" behaviour. The two assertions now expect 409 `edit_stale`. No other
   unowned file was touched.
6. No live founder-video run, per the track rules. No server was started.
