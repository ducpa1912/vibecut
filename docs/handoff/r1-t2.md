# R1 T2 — Studio rights UI

**Branch:** `rv/r1-t2-studio-rights`
**Base:** `refactor-1-base` (`1eb472b`)
**Scope:** REFACTOR_PLAN §2 T2. No backend, `api.js`, test, or plan files changed.

## What was built

- **Setup → Rights → Rights lock** switch with the exact help text from the plan. It saves through `POST /api/settings` as `rights: {lock: bool}` and reads the value back from `GET /api/rights/policy`.
- **Import** reads `GET /api/rights/policy` on mount and on Refresh. The own-footage tick is shown and required only while `needs_import_tick` is true. With the lock off, the tick is hidden and import sends no rights value. While the policy is loading or unreadable, Import stays disabled instead of guessing.
- **Check** reads `job.rights_policy` from `GET /api/jobs/{id}` (global policy only as a fallback when an older server omits the field). The rights tick appears only when the lock is on and this video has no rights note. Ticking records the note through the existing `POST /api/jobs/{id}/rights`; Check no longer sends an `attestation` body field.
- **Clean** reads `job.rights_policy`, gates every kind from `policy.clean[kind]`, and shows the server reason on each Check row (chip title and row text). Watermarks and screen text stay refused. With the lock off, old captions are open while a handle or logo shows a per-video "this is mine" tick. Ticking records the note on the job and re-reads the policy.
- **localStorage attestation removed.** `vibecut.studio.attested.*`, `rememberAttestation` and `hasAttestation` are gone. The browser keeps only in-memory checkbox state. The Clean prefill marker remains; it is not a rights source.
- **No local policy decision.** The UI only renders `lock`, `needs_import_tick`, `attested` and `clean[kind]` from the server. A missing policy keeps the conservative gate and shows a loading/error message.

## APIs

New contract read from T1 (not yet present on this branch base):

- `GET /api/rights/policy` → `{lock, attested, needs_import_tick, clean: {kind: reason|null}}`
- `GET /api/jobs/{id}` → adds `rights_policy`
- `POST /api/settings` → accepts `rights: {lock: bool}`
- Import routes → `rights` optional with the lock off; 409 with the lock on when missing

Existing routes reused:

- `POST /api/jobs/{id}/rights` (`attested: true`, `source: "check"`)
- `GET /api/jobs/{id}/check`, `POST /api/jobs/{id}/check`
- `POST /api/jobs/{id}/cleanup/layers`
- `GET /api/jobs`, `POST /api/jobs/{upload,path,from-url}`
- `GET /api/settings`, `GET /api/audio/engines`

`api.js` was not changed. `import.js` uses the existing exported `request()`.

## Known gaps

- T1 is not in this worktree. The new routes and `job.rights_policy` are coded against REFACTOR_PLAN §1 and are unverified live until T1 merges.
- The per-video handle tick appears only when the server's `clean.handle_or_logo` reason is `attestation_required`. If T1's legacy `job_attested` rule reports a lock-off job as attested, the server returns no reason and Studio shows no tick. Studio follows the server rather than inventing a local gate.
- If `job.rights_policy` is absent (only possible on an older server), Check and Clean fall back to `GET /api/rights/policy`. That global payload cannot know a single job's note, so Clean stays locked rather than opening on a guess.
- Clean records the per-video tick through the existing rights route with `source: "check"`, because that route's current `Literal` accepts only `import` and `check`. The tick is still stored per video; no new source value was invented.
- The Clean reason is displayed in the row text and chip `title`, not inside the chip label itself. The chip keeps the kind name so the list stays scannable.
- Clean auto-fill now ignores the old `clean_prefill[].enabled` flag and relies on the policy gate, so it works with the lock off. It still never opts into handles automatically.
- No automated T2 test file was added: `tests/test_studio_js.py` is not in T2's ownership list. The helper matrix above is the repeatable manual check.

## Founder manual test

Use video **A**: your own footage with baked-in subtitles or captions. Use video **B**: your own footage with a handle/logo, plus any clip with a platform watermark or screen-recording UI text.

| Action | Intent | Expected | Result |
|---|---|---|---|
| Setup → Rights: read the section without changing anything. | Default lock state. | Rights lock is On, and the help text matches the plan exactly. | |
| Setup → Rights: turn Rights lock Off, close Setup, reload the page, reopen Setup. | The setting persists on the server. | The switch is still Off after the reload. | |
| Import video **A** with the lock On. | The import tick is required. | "Import video" stays disabled until the own-footage tick is set. Import then starts. | |
| Setup → Rights: turn the lock Off. Import video **A** again. | Import is open with no box. | No rights tick is shown and Import starts straight away. | |
| Open Check for the lock-off import. | Check does not ask again. | No Rights card and no rights tick. Clean is open for old subtitles. | |
| Edit → Clean on video **A** with the lock Off. Add a burned-in subtitle region. | Old captions are open. | The region can be added and saved with no rights tick. | |
| Open video **B** with a handle/logo and the lock Off, then Edit → Clean. | Handle/logo needs its own tick. | The handle row says it needs the per-video "this is mine" tick; Add stays disabled until the tick in Rights. After ticking, Add works. | |
| With either lock state, try to clean a watermark or screen-interface text. | Fixed refusals. | The row says "Never cleaned" / "Never" and the server reason is shown (for example the watermark reason). Add stays disabled. | |
| Check a Clean row for a blocked region. | Server reason is visible. | The row text and chip tooltip show the policy reason, not a generic "locked". | |
| Setup → Rights: turn the lock back On, then reopen an Edit saved while the lock was Off. | Old Edits are not rewritten. | The old Edit still shows its Clean layers. Changing a Clean layer now asks for the rights note before saving. | |
| Clear the browser's localStorage, reload Studio with the lock On, and open Check on a video imported with the tick. | No browser attestation source. | Check still treats the video as attested and shows no tick. Import/Check/Clean keep working. | |
| Stop the server (or block `/api/rights/policy`), reload Import. | No policy guess. | Import shows "The rights policy could not be read…" and stays disabled. It does not silently import. | |
