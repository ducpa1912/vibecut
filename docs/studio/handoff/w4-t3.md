## Built scope

1. **Legacy caption tracks migrate to Edits.** `migrations.py` scans each job's
   `story_captions` table and creates a captions-only 9:16 Edit for every story
   that has a valid track. The pointer lands in
   `job["story_edits"]["{set_id}:{story_id}:9:16"]`.
2. **Classic keeps reading and writing.** The migration never removes or
   rewrites `job["story_captions"]`, the caption track files, or the job's
   `updated` timestamp. Classic `GET/PATCH /api/jobs/{id}/captions/{track}`
   still works after migration.
3. **Legacy render targets stay intact.** A migrated 9:16 story render resolves
   the new Edit and the same caption track. A 4:5 render with no 4:5 Edit keeps
   the old plan + `story_captions` path.
4. **Clean is on by default.** `VIBECUT_ENABLE_CLEANUP` unset, blank or unknown
   keeps Clean on. `0`, `false`, `no` and `off` disable it. The rights routes
   stay available either way, and the server-side own-footage gate still runs
   before any Clean save.
5. **Startup hook.** `app.py` gained one import line and one lifespan line:
   `migrations.migrate_all(JOBS)` after `recover_jobs()`. No other app behavior
   changed.

No Edit schema change was needed. Old Edit sidecars that pass
`edits.normalize_edit` remain valid, and migration writes the same merge schema
the Studio routes use.

## Migration behavior

**Discovery.** For each clip set/story, candidates are:

1. `job["story_captions"]["{set_id}:{story_id}"]` (authoritative current track);
2. the newest `job["renders"][...]` record that carries both
   `set_id`/`story_id` and `caption_track_id` (fallback for jobs that predate
   the story-caption pointer).

A candidate is skipped if the track file is missing, the track's stored
`job_id` belongs to another job, the story has no clips, or the story id is not
a valid Edit id.

**Creation.** The Edit is version 1, parent `null`, aspect `9:16`, with:

```json
{
  "captions": {"track_id": "cap_…", "style_id": "…", "enabled": true},
  "clean": [],
  "motion": [],
  "graphics": [],
  "color": {"preset": "none", "...": "defaults"},
  "reframe": {"mode": "auto", "...": "defaults"},
  "audio": {"mode": "original", "...": "defaults"}
}
```

The sidecar is written with `edits.save_edit` (immutable), the pointer with
`edits.set_pointer`, and a best-effort history entry with
`edits.append_history`. `job.json` is replaced atomically.

**Idempotency and reset.** Re-running is a no-op when the pointer exists. It is
also a no-op when any immutable version exists for that story/aspect, so a
deliberate Studio reset (`DELETE /edits/{id}` clears the pointer but keeps
versions) is not recreated on the next startup.

**Failure isolation.** `migrate_all` scans `JOBS/*/job.json`, records a broken
job in the summary, logs it, and continues. One bad job cannot block startup or
another job.

**No side effects.** Migration starts no render, probes no media, calls no
network, and leaves artifacts and `updated` untouched.

## Known gaps

1. **Classic caption edit after startup does not update an existing migrated
   Edit.** The Classic PATCH updates `story_captions` to a new track id. A
   migrated Edit stays immutable and still references the old track, so a
   Classic story render after that edit prefers the Edit's old track. The
   migration is startup-only and does not run a watcher. Re-open Studio and
   select the new track, or create a fresh Edit, to publish the Classic edit.
   This is the one place where Classic fallback is read/write compatible but
   not instantly re-render compatible.
2. **Only 9:16 is migrated.** A legacy story has one track, not per-aspect
   tracks. 4:5 keeps the Classic path until the user creates a 4:5 Edit. This
   is intentional and covered by `test_legacy_4_5_render_stays_on_the_classic_path`.
3. **Standalone target caption tracks are not migrated.** Only tracks linked to
   a story by `story_captions` or a story render record can become an Edit.
   Tracks built for a 15/30/60 rip have no story key.
4. **Migration runs at startup, not on import.** A brand-new job that gets a
   legacy story track from the Classic UI while the server is already running
   has no Edit until the next restart. Studio creates its own Edit normally.
5. **`docs/shared/cleanup.md` is stale.** It still says Cleanup is off by default.
   The file is outside T3 ownership; README now carries the current default.
   The W3 live checklist also starts the app with `VIBECUT_ENABLE_CLEANUP=1`,
   which is now redundant but harmless.
6. **No real-ffmpeg smoke was run.** T3 changes no render code. The 4:5 and
   9:16 selection tests stub the render queue and assert the chosen Edit/track;
   the existing render suite covers the actual ffmpeg path.
7. **No Studio UI ownership.** T3 does not wire the Clean or Finish screens;
   T4 owns those. The migration only makes the data those screens read valid.
8. **A dangling `story_edits` pointer is left alone.** The migration skips a
   key whose pointer exists even if its sidecar is missing; it does not repair
   or clear corrupt user state.
