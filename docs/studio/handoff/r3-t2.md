## Route contract

```http
GET /api/artifacts?q=&job_id=&shape=9:16&limit=60&offset=0
```

Response:

```json
{
  "artifacts": [
    {
      "artifact_id": "art_…",
      "job_id": "7610134fee5e",
      "job_title": "JOYLO AV1 talking head",
      "source_label": "source.mp4",
      "story_id": "st_…",
      "story_title": "AI security test",
      "aspect": "9:16",
      "shape": "9:16",
      "quality": "final",
      "target": 30,
      "version": 2,
      "version_label": "v2",
      "created": 1793186105.5,
      "date": "2026-10-28",
      "size": 1048576,
      "status": "ready",
      "pinned": false,
      "url": "/api/jobs/7610134fee5e/artifacts/art_…/media/reel.mp4",
      "media_url": "/api/jobs/7610134fee5e/artifacts/art_…/media/reel.mp4",
      "poster_url": "/api/jobs/7610134fee5e/artifacts/art_…/media/poster.jpg",
      "thumb_url": "/api/jobs/7610134fee5e/artifacts/art_…/media/poster.jpg",
      "download_url": "/api/jobs/7610134fee5e/artifacts/art_…/media/reel.mp4",
      "duration": 52.9,
      "width": 1080,
      "height": 1920
    }
  ],
  "total": 1,
  "offset": 0,
  "limit": 60,
  "q": "",
  "job_id": "",
  "shape": ""
}
```

- **Sort:** `created` descending, then `artifact_id` descending, so repeated calls are stable.
- **Pagination:** `limit` clamped 1–200 (default 60); `offset` clamped to ≥ 0.
- **Search:** `q` splits on words and requires every term in id, job/source/story titles, shape, quality, version, date or status.
- **Filters:** `job_id` and `shape` are exact matches.
- **Versions:** stored `version` wins. An old manifest without one gets a deterministic sequence inside its job + story (or target) + aspect group, ordered by creation time. Nothing is written back.
- **Media:** URLs exist only when the media file is present; a failed artifact still lists with `url: null`.
- **Robustness:** an unreadable `job.json` still lists its valid artifacts with the job id as label; corrupt manifests, invalid artifact ids, symlinked job directories and unreadable artifact directories are skipped.
- **Read-only:** no `update_job`, no `ensure_job_schema`, no index refresh, no adoption, no file creation. A test snapshots `job.json`, `manifest.json` and `index.json` before and after two requests.

## app.py integration (required, owned by T3)

The route is not registered until app.py adds these exact two lines, near the other `include_router` calls:

```python
import routes_library
routes_library.install(app)
```

`install(app)` pins `app.JOBS` on `app.state.library_jobs_dir` and calls `app.include_router(routes_library.router)`. The bare alternative also works when `VIBECUT_DATA` is set:

```python
import routes_library
app.include_router(routes_library.router)
```

Until that lands, the live app returns the old 404 for `GET /api/artifacts`.

## Studio behaviour

- **Finished** is the default tab on open. It calls `GET /api/artifacts`; rows show poster, story title (falling back to job/source/artifact id), then shape · quality · version · date · size, then job/source context, plus a status chip. Ready rows have Play (inline `<video>`), Download and Open in Finish. A failed row keeps its status and Open in Finish but no dead media links.
- **Sources** calls the existing `GET /api/jobs` and keeps the click-to-open action. The title is job title, then first story title, then a non-generic filename stem, then `Source · date · #id`. `source.mp4` is never used as the title.
- **Search** is shared and debounced. It filters Finished server-side and Sources through the existing `q` parameter.
- **Tabs** use `role="tablist"`/`role="tab"`, `aria-selected`, roving `tabindex`, Left/Right/Home/End. Opening the dialog focuses search. Escape/backdrop/close keep the native dialog behaviour.
- **Open in Finish** closes the dialog, sets the artifact's job and goes to `#/finish`. The shell's hash contract is only `#/<step>`; story and shape are not carried into Finish (see gaps).

## Known gaps

1. **Registration:** app.py is owned by T3. Until the two-line integration lands, the route is 404 in the app. The router itself is covered by 9 tests on a standalone FastAPI app.
2. **Story/shape are not carried into Finish.** The shell only supports `#/<step>`. Open in Finish correctly opens the artifact's job and the Finish step, but Finish starts on its first story and default 9:16 shape. Carrying `story`/`shape` needs a hash/query contract in shell.js plus a matching option in finish.js (T3 owns finish.js).
3. **Canonical artifacts only.** The library reads `jobs/*/artifacts/*/manifest.json`; legacy `job["renders"]` projections that have no manifest are not listed. Listing or adopting them would need a write (adoption) or a second read-only legacy projection; this track kept the strict read-only contract. Current renders in the founder build already create manifests, so the four-render path is covered.
4. **No “load more” control in the dialog.** The route paginates (60 default, 200 max), but the Finished tab requests the first page only. More than 60 artifacts would need a follow-up control.
5. **No review/approval state.** That is deferred in round 6 and outside T2. Rows show render status and pin flag only.
6. **No automatic refresh while open.** Opening the dialog refreshes the list; a render that finishes while the dialog stays open appears on the next open/refresh.
