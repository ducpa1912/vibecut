## What was built

1. **Packet v2.**
   - `SCHEMA` is `vibecut.publish_packet/2`; `vibecut.publish_packet/1`
     packets still load and verify, so old links are not orphaned.
   - A packet now carries the primary artifact's `edit.json`, `audio.json`
     and `music.json` at its root. Multi-artifact packets keep the first
     (primary) document at the root and put other artifacts' documents under
     `sidecars/<artifact_id>/`.
   - Each `media[]` row carries `identity`, `edit`, `audio`, `music` and
     `layer_assets` refs, so 9:16 and 4:5 can point at different Edit
     versions.
   - `layer_assets` copies and hashes the LUT and bundled sticker PNGs an
     Edit draws with. A caption font is copied when the style names a real
     file. A missing or changed asset refuses the packet
     (`layer_asset_missing` / `layer_asset_hash_mismatch`, 422) instead of
     shipping art that no longer matches the Edit.
   - `edit.json` is path-normalised for the packet: LUT paths point at
     `assets/<kind>/…`; music/voice paths are basenames. No source path, job
     directory or absolute path is serialized. The Edit `id`, `hash` and
     `version` are kept so the packet still names the exact Edit version.
   - `IDENTITY` is a canonical hash over `edit.hash`, `transcript_id`,
     audio document hash, music file hash and layer-asset hashes. It is part
     of the packet id seed, so changing any quoted input changes the packet.
   - `audio.json` records mode, the adapted AudioPlan, translate target/mode,
     voice engine/model/voice id, `ai_voice`, and `transcript_id`. This is the
     §7.3 provenance block.
   - `music.json` follows §8.5: source type, file hash, licence/attestation,
     provider metadata, brief, BPM, in/out points, duration and lock flag.
     It prefers the job's `audio/music.json`, then the locked history entry,
     then the Edit's own music fields. Original audio with no bed produces no
     `music.json`.
   - Covers use the same `render.render_story_frame` graph as
     `GET /api/jobs/{job_id}/edits/{edit_id}/frame`. If that frame cannot be
     made, the old ffmpeg/media-poster path remains the fallback and the cover
     row says which path ran (`frame`, `ffmpeg` or `poster`).
   - Packet integrity covers every media, caption, cover, copy, document and
     layer-asset file; the ZIP must match the manifest byte for byte.

2. **Packet route for T4.**
   - `POST /api/jobs/{job_id}/artifacts/{artifact_id}/packet`
   - Body: `story_id`, optional `artifact_ids` (must contain the path id if
     supplied), `titles`, `description`, `hashtags`, `cover_times`,
     `pin_comment`.
   - Returns the same public packet manifest as
     `POST /api/jobs/{job_id}/packets` (`packet_id`, `zip_url`,
     `packet_url`, every v2 ref). The existing multi-artifact route still
     works.
   - Packet artifact refs are still written to `job["packet_refs"]`, so
     delete/clean protection sees the new route too.

3. **Artifact identity.**
   - `ArtifactSpec` gains optional `transcript_id`, `audio_hash` and
     `music_hash`. They are added to the canonical payload only when present,
     so legacy artifact ids stay byte-stable.
   - `build_spec()` takes the transcript id from `plan["_caption_track"]`
     when captions are rendered, and takes `audio_hash`/`music_hash` from an
     AudioPlan when the caller supplies one (`artifacts.audio_hashes()`).
   - `manifest.json` now records `edit_hash`, `edit_id`, `edit_version`,
     `transcript_id`, `audio_hash` and `music_hash`. Legacy manifests keep
     working; the id is unchanged by this display metadata.
   - `save_manifest()` resolves the exact Edit sidecar by content hash and
     stamps `edit_id`/`edit_version`. It prefers the job's current pointer for
     that set/story/aspect, otherwise the newest matching version.

4. **Review links show the Edit version.**
   - `artifacts.version_info()` adds `Edit vN` to the banner label and returns
     an `edit` object. `GET /r/{token}` already renders that label, so the
     banner reads `v2 · Edit v3 · current` (or `superseded by …`).
   - `render_record()` and the public manifest expose `edit_id`,
     `edit_hash`, `edit_version`, `transcript_id`, `audio_hash` and
     `music_hash` for Artifacts & Shares and Studio Finish.

5. **Beat grid reaches Edit compile.**
   - `render.edit_beat_grid(job_dir, edit, audio_plan)` returns the locked
     bed's grid only when the Edit has motion/graphic boundaries already
     sitting within `fx.BEAT_WINDOW` of a beat. Unlocked beds, original audio
     and off-beat edits are left alone.
   - `render.render_reel()` passes that grid to
     `compose_render.compile_edit(beats=…)`. The stored Edit and
     `edit.hash` never change; compile output reports `beat_snap`.
   - Packet covers use the same grid so a cover matches the final story
     render when beat snap is active.

6. **Dub target reaches the AudioPlan adapter.**
   - Edit `audio.translate` is now `{target, mode}`. `target` is a language
     code (`zh`, `pt-BR`); `mode` is `literal`, `smooth`, `viral`, `fun`,
     `creative`, `sad` or `chill`, default `literal`.
   - `audio.plan_from_edit()` already copied `translate`; the schema now lets
     an Edit carry it. The packet builder and the artifact adapter call
     `plan_from_edit` with the Edit audio section, so the target is present in
     `audio.json` and in the adapter's plan.
   - Omitting `translate` (or sending `null`) leaves the Edit hash unchanged.

Packet manifest additions:

```text
schema                  vibecut.publish_packet/2
identity                {schema, edit{id,hash,version,aspect}, transcript_id,
                         audio_hash, music_hash, layer_assets[], hash}
edit / audio / music    {file, bytes, sha256, …} or null
layer_assets[]          {kind, id, file, bytes, sha256}
media[]                 + identity, edit, audio, music, layer_assets[]
```

Document schemas:

```text

audio.json              vibecut.packet_audio/1
music.json              vibecut.packet_music/1

```

```text

```

Artifact schema addition:

```text

manifest.edit_id / manifest.edit_version                 display metadata
```

## Known gaps

1. **The queue call does not pass an AudioPlan to `artifacts.build_spec`.**
   `app.py` is limited to import/include lines this track, so the production
   artifact id still covers `audio_sig` (the canonical AudioPlan signature,
   which includes the locked music `file_hash`) and `transcript_id`; the new
   explicit `audio_hash`/`music_hash` fields are populated when a caller
   supplies `audio_plan`. Packet v2 always carries the exact audio/music
   hashes in `identity`. Wiring the queue is a one-line app call for the
   merge owner or T4.
2. **`edit.json` paths are packet-relative.** The directory has the exact
   Edit `id`/`hash`/`version`, but the LUT path is rewritten to the packet's
   bundled asset. Re-saving `edit.json` as-is would produce a different Edit
   hash until paths are restored; the packet is a hand-off record, not an
   editable source.
3. **Story render still does not mix Edit audio.** `audio.plan_from_edit`
   receives the Edit's translate target in the packet/artifact adapter path,
   but the story render path passes no `audio_plan` and therefore does not
   speak the dub. That wiring is T4/app work; the schema and adapter are
   ready.
4. **Beat snap only fires when a boundary is already within ±120 ms of a
   beat.** An Edit authored far from the grid keeps its times. Beat-snapped
   arrows/underlines/stickers still draw statically; per-frame draw-on is a
   later render item.
5. **Cover fallback is silent.** If the frame render fails, the packet uses
   the rendered media/poster and records `"ffmpeg"`/`"poster"` in
   `covers[].source`. There is no warning in the public manifest beyond that
   source value.
6. **No Studio ownership.** T1 changed no `static/**` file. T4 must call
   `POST /api/jobs/{job_id}/artifacts/{artifact_id}/packet` and read
   `media[].edit`, `media[].audio`, `media[].music`, `identity` and
   `layer_assets`.
7. **No founder A/B live run.** The founder manual table below is the
   acceptance path for JOYLO AV1 and rednote.
