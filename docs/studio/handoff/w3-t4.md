## What was built

### 1. `static/studio/check.js` — Source Check screen

- Loads the existing `GET /api/jobs/{id}/check` report and starts a pass with
  `POST /api/jobs/{id}/check`.
- Sends the own-footage attestation with the Check request. If the W3 T2
  `POST /api/jobs/{id}/rights` route exists, it is called first; on this base
  that route returns 404 and Check's own attestation field is the fallback.
- Polls queued/running passes every 1.8 s, shows progress, and clears the status
  when the report is ready or failed.
- Shows the recommendation in plain language (`clean_then_compose` →
  "Clean the old text, then add your own"), reasons, warnings, source facts,
  text tracklets with source-box sketches, audio/music/faces/quality and the
  rights state.
- Watermark tracklets are always shown as refused: "Use your original file —
  it has no watermark."
- Shows 40 tracklets first with a "Show all N regions" button so a
  screen-recording source with over 100 OCR regions does not produce one huge
  page.
- "Open Edit" appears only when a clip set with stories exists.

### 2. `static/studio/edit/layers/clean.js` — Clean controls

- First open auto-fills Clean from `report.clean_prefill` when the Edit has no
  Clean layers, the report has text, and rights are allowed. This is the
  founder decision "Check pre-fills the Clean layer"; the action is a normal
  Edit save and the notice says to remove anything unwanted. It runs once per
  job/story/aspect.
- Mid-frame subtitles get `blur` plus an opaque `plate`, matching the plan and
  W3 T2's mapping. Watermarks are never offered. `screen_text` (arriving with
  T2) and `action: "none"` are skipped and labelled "Never".
- Suggested regions, existing layers, a selected-layer editor and a manual
  "Add box" action cover `plate`, `blur`, `mask` and `crop_guard`.
- Boxes and ranges are **source** coordinates and source times (`edits.py`
  contract). Box values are edited in source-frame percentages.
- The editor exposes colour, opacity and radius for plate/mask/blur, source
  time ranges, label, removal and "Add story range".
- Blur radius is capped adaptively from the source box size
  (`floor(min(w·srcW, h·srcH) / 4) - 1`, 2–12). FFmpeg 9.0.2 rejects a
  `boxblur` chroma radius that is too large for a small crop; the UI avoids
  creating a layer that cannot render. T2 also caps at 12 for the same reason.
- Quality warnings from Check, quality issues and the mid-frame warning are
  shown in the panel. Rights are shown and the panel locks adding when the
  report does not allow cleaning.
- Respects the backend limits: at most 32 Clean layers per edit, at most 40
  suggestion rows, and a clear "cover slots are used" state.
- Labels are sanitised against `edits._FORBIDDEN_RE` words (inpainting,
  watermark, avatar, stock B-roll, voice cloning) so an OCR label can never
  make an otherwise valid save fail.

### 3. `static/studio/edit/layers/effects.js` — Motion and graphics

- Motion: `punch_in`, `snap_zoom`, `push`, `shake`, with start/end, amount,
  ramp and shake seed.
- Graphics: `arrow`, `circle`, `underline`, `progress_bar`, `sticker`, with
  anchor, output-space box, colour, thickness, opacity and sticker asset.
- Output coordinates are used, as required for graphics.
- Add/remove with the 8-motion and 32-graphics backend limits.
- Beat snap uses the existing `GET /api/audio/beats` for the music bed chosen
  in Audio. It snaps start/end to the tempo grid within 120 ms and updates the
  visible inputs after the save. Uploaded beds have job-relative paths on this
  base and the beat route only accepts absolute paths; the panel says so
  plainly instead of pretending snapping worked.
- Sticker assets are not installed on this base. Adding a sticker requires a
  real asset id and 16–64 character hex hash; no fake asset is invented.

### 4. `static/studio/edit/layers/audio.js` — Sound

- Audio mode: original, original + music, voice-over, dub, music only.
- Voice: available engines from `GET /api/audio/engines`, voices from
  `GET /api/audio/voices`, a language-aware default (Chinese story → a zh
  voice, English → an en voice), rate, and a `POST /voice/sample` preview.
- Music: library candidates from `GET /api/audio/music?source=library`,
  per-job upload through `POST /audio/music-upload`, licence note, clear
  selection, and `original_bed` chosen automatically when a bed is selected.
- Ducking slider (−60..0 dB) and loudness/true-peak targets.
- Saves a valid `audio` layer (mode, duck, loudness, voice, one bed) through
  the existing Edit PATCH route. This panel is the only one that writes with a
  direct PATCH because `panelCtx` has no `setAudio` and `edit/index.js` is
  outside this track's ownership. On success it updates the Edit object in
  place, enables Undo, updates the audio lane label and tab count, and keeps
  the editor's next save on the new head. A 409 reloads the current head once
  and retries.
- No cloud call happens unless the creator picks a cloud voice and presses
  Preview. Library and upload always work offline.
- Cloud music generation/candidate routes are not on this base. The panel
  shows library candidates and upload; it does not claim generated candidates.

## APIs used

| Method | Path | Use |
|---|---|---|
| `GET` | `/api/jobs/{id}` | Open video, source facts |
| `GET` | `/api/jobs/{id}/clip-sets` | "Open Edit" availability |
| `GET` | `/api/jobs/{id}/check` | Load a report / poll |
| `POST` | `/api/jobs/{id}/check` | Start or re-run Check; sends `attestation` |
| `POST` | `/api/jobs/{id}/rights` | Best-effort W3 T2 integration; 404 on this base, Check attestation fallback |
| `GET` | `/api/jobs/{id}/edits/current` | Current edit in the audio 409 retry |
| `PATCH` | `/api/jobs/{id}/edits/{edit_id}` | Audio layer save |
| `GET` | `/api/audio/engines` | Voice engines |
| `GET` | `/api/audio/voices?engine=…` | Voice list |
| `POST` | `/api/jobs/{id}/voice/sample` | Voice preview WAV |
| `GET` | `/api/audio/music?source=library` | Music candidates |
| `POST` | `/api/jobs/{id}/audio/music-upload` | Upload a bed |
| `GET` | `/api/audio/beats` | BPM for beat snap |

Clean/effects use the existing Edit setters in `edit/index.js`
(`setClean`, `setMotion`, `setGraphics`). Frame and proxy routes are consumed
by the existing preview module, not re-implemented here.

## Known gaps / exceptions

1. **Fixture env vars were not set.** The live run used the two real founder
   files found by path (the same paths W3 T2 used). Re-run with
   `VIBECUT_FIXTURE_A` / `VIBECUT_FIXTURE_B` before final acceptance if those
   names point at different files.
2. **Check's sampled Vision helper failed once, then succeeded.** The first A/B
   runs reported `ocr_available=false` and `text_unconfirmed`; a UI re-run
   reported confirmed text with 132 (A) and 17 (B) tracklets. Scene OCR
   tracklets were available in both cases. The Check backend owner should
   confirm the sampler's helper build/race; the UI displays the warning
   honestly and still pre-fills from found text.
3. **`edits.MAX_TIMELINE` is 3600 s** while the plan targets 90-minute
   sources. A Clean range beyond one hour will be rejected by the Edit API.
   This is a core contract gap outside T4 ownership. The live fixtures are
   under 90 s.
4. **`edits.MAX_CLEAN` is 32.** A screen recording can produce more than 100
   tracklets; only 32 covers fit in one Edit. The UI caps and explains this.
   A larger cap or a server-side selection strategy belongs to core/Clean.
5. **Uploaded music beat snap is unavailable on this base.** The existing
   `GET /api/audio/beats` accepts an absolute track path; uploads are saved
   job-relative. A was snapped by patching the Edit's `audio.music.track` to
   the absolute path as the documented manual-JSON fallback. B shows the
   unsupported message. W3 T3 should resolve job-relative paths or expose exact
   beat times.
6. **Beat snap uses a BPM grid.** The existing route returns BPM and a beat
   count, not beat timestamps. The panel labels this and snaps within 120 ms.
7. **Cloud music candidates are not wired.** W3 T3's
   `/music/brief`, `/music/candidates` and `/music/lock` routes are not on this
   base. Library tracks and job upload are the provided candidates; no
   generation is faked.
8. **Audio mix/dub rendering is not on this base.** The panel saves a valid
   `AudioPlan`, but the W3 T3 mixer/dub renderer is not merged here. The
   panel says the mix is stored in the edit; it does not claim a rendered mix.
9. **Clean layers are built client-side from Check pre-fill.** W3 T2's
   `POST /cleanup/layers` is not on this base. The mapping mirrors T2:
   mid-frame subtitle → blur + plate, title → mask, lower third/credit → blur,
   screen text → never, watermark → never, handle → off by default. After T2
   merges, consider switching to the server route for the single policy gate.
10. **Rights enforcement is only as strong as the base.** This branch records
    the attestation in the Check report/job.check. T2's `routes_edits` rights
    gate and `/rights` route are not on this branch; Check also calls `/rights`
    best-effort, so after merge the server record is created. The UI locks
    adding Clean layers when the report does not allow cleaning.
11. **Sticker assets are not installed.** A sticker needs a real bundled asset
    id/hash; the picker arrives with the Compose track.
12. **Audio uses a direct Edit PATCH.** There is no `setAudio` in the editor
    context and `edit/index.js` is outside ownership. It updates the edit in
    place and handles one 409 reload/retry; a second concurrent editor is not
    supported beyond that. The index's own save status stays "Saved".
13. **Import still navigates to Stories.** `import.js` / `shell.js` are outside
    this track. Check is reachable from the rail and works; making Check the
    automatic next step is a follow-up in the shell track.
14. **A preview at 0:00 / small scrub times can show the placeholder until the
    frame returns.** Scrubbing to `0:20` (B) and `0:05` (A) produced the exact
    frame. This is the existing preview/frame timing, not a new control.
