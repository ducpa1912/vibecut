## What was built

### 1. Tracklets → Edit Clean layers

`cleanup.tracklet_clean_layers()` turns the stored Check tracklets into
`edits.normalize_clean`-ready layers:

| Detected kind | Clean layer |
|---|---|
| `subtitle` in the caption band | `plate` |
| `subtitle` mid-frame | `blur` (radius 12) **plus** an opaque `plate` cover |
| `title` | `mask` |
| `lower_third` | `blur` |
| `credit` | `blur` |
| `handle_or_logo`, attested + explicit opt-in | `crop_guard` at an edge, else `blur` |
| `handle_or_logo`, otherwise | refused (`attestation_required` / `opt_in_required`) |
| `watermark` | always refused |
| `screen_text` | never cleaned, `action: "none"` |

- Boxes are source-normalized 0–1 (`Clean` coordinate contract).
- Ranges are absolute source times, merged and capped at 64 per layer.
- Layer ids are `cl_<tracklet id>`; a mid-frame subtitle cover is
  `cl_<tracklet id>_plate`.
- The single policy gate is `detect.cleanup_block_reason(kind, attested=...)`.
  Cleanup never re-implements a kind rule.

### 2. `screen_text` kind

`detect.KINDS` now includes `screen_text`. Classification is deliberately
narrow but covers real screen-recording chrome:

- known status/tab/navigation labels (`9:41`, `Search`, `Home`, `Profile`,
  `For You`, `Settings`, battery/`5G`/`Wi-Fi`, …) in a small edge block;
- an unknown short, mixed-case top-status or bottom-tab label in a small block;
- an all-caps corner mark stays `handle_or_logo`, not `screen_text`;
- platform marks still classify as `watermark` first.

`clean_prefill` emits `action: "none"`, `enabled: false`,
`blocked: "screen_text"` for every screen-text tracklet. `screen_text` is not
in the recommendation's cleanable set, so a source with only UI text is
`compose`, never `clean_then_compose`.

### 3. Residual-OCR quality report

`cleanup.residual_report()` maps each Clean box from source coordinates through
the compiled segment crop into output coordinates, then checks OCR lines on
rendered output frames inside those cleaned regions.

Report fields: `frames_sampled`, `frames_with_ocr`, `residual_frames`,
`residual_pct`, `target_pct` (0.5), `pass`, `unlocated_text`, per-layer
`residual_frames`/`residual_pct`, and per-frame samples. `cleanup.face_overlap_report()`
reports Clean regions that overlap a Check face.

The route renders **Clean + reframe only**: motion, colour, graphics and
captions are excluded from the measurement edit so new captions cannot be
counted as residual old text.

### 4. Server-side rights attestation

`job["rights"] = {"attested": bool, "at": <server ts>, "source": "import"|"check"}`.
The rights routes are outside the `VIBECUT_ENABLE_CLEANUP` feature gate.

`routes_edits` enforces the gate on every save that contains Clean layers
(create, patch with `clean`, undo, restore). It reads `job["rights"]` only;
no request body or browser storage is trusted. A job with no `rights` record
at all is treated as a pre-Wave-3 legacy job and keeps working; once a rights
record exists, an unattested record blocks Clean saves with `409`.

## Endpoints

| Method | Path | Behaviour |
|---|---|---|
| `POST` | `/api/jobs/{id}/cleanup/layers` | Build Clean layers from the stored Check report. Body: `{tracklet_ids?: [..], include_handles?: bool}`. `409` when Check has not run or rights are not attested; `422` for unknown tracklet ids. Always uses server-side rights. |
| `POST` | `/api/jobs/{id}/cleanup/residual` | Render Clean-only frames and return the residual-OCR report. Body: `{edit_id, times?: [..], start?, end?, fps=1.0, max_frames=120, quality="final"}`. `404` unknown Edit, `409` analysis/story missing, `422` no Clean layers or bad times/quality. |
| `GET` | `/api/jobs/{id}/rights` | `{rights: {attested, at, source}}`; defaults to unattested/null. |
| `POST` | `/api/jobs/{id}/rights` | Body `{attested: bool, source: "import"|"check"}`. Stores the record on the job and returns it. |
| `POST` | `/api/jobs/{id}/cleanup/plan` | Unchanged legacy planner (still gated by `VIBECUT_ENABLE_CLEANUP`). |

The two new cleanup routes are gated by `VIBECUT_ENABLE_CLEANUP`, matching the
existing Cleanup Kit. Rights are not gated.

## Rights integration for T4

At Import/Check, call:

```http
POST /api/jobs/{job_id}/rights
{"attested": true, "source": "import"}
```

Then build layers with `POST …/cleanup/layers` and write the returned `layers`
into the Edit `clean` field. Do not send attestation on the Edit save; the
server reads `job["rights"]`. Passing `attestation` to the legacy plan body is
still supported for the existing planning API but is not the Clean layer path.

## Known gaps / exceptions

- **Real fixture A still has a few screen-recording headings classified as
  `subtitle`/`title`.** The editor offers those as Clean targets once rights
  are attested; 123 of 132 tracklets are `screen_text` and every screen-text
  entry is `none`. Manual review is still required.
- **The shirt mark on A is a graphic, not OCR text.** No `handle_or_logo`
  tracklet exists for it, so no Clean layer targets it. The rights gate still
  locks all Clean layers before attestation (`409`).
- **Legacy rights fallback.** A job with no `job["rights"]` key at all can
  still save Clean layers; this is for pre-Wave-3 jobs and existing tests.
  Any job with a rights record (all new Import/Check flows) is gated. T4 must
  call `POST /rights` at Import/Check.
- **`screen_text` is a heuristic.** It handles OCR-readable UI chrome. It
  cannot detect non-text UI glyphs, icons, or a screen recording whose status
  bar is illegible to Vision.
- **Residual route ignores motion/colour/graphics/captions by design.** It
  measures the Clean regions on the reframed Clean-only graph. A final frame
  with motion can shift the region slightly; the acceptance target is measured
  on the cleaned source geometry. Clean boxes are padded (≤2% x, ≤4% y) to
  cover glyph edges; B needed that pad to reach 0.0%.
- **Face overlap uses analysis faces or `attention.face`.** A has 33 faces
  checked, B has none. If neither signal exists, `faces_checked` is 0 and
  `overlap` is false.
- **`compose_render` box-blur radius >12 fails on this ffmpeg build.** FFmpeg
  9.0.2 rejects `boxblur=24:2` with “Invalid chroma_param radius value 24,
  must be >= 0 and < 13”. T2 emits `radius: 12` so built layers render. A
  manual Edit Clean layer with `radius: 24` still hits this pre-existing
  `compose_render.py` bug, which is outside T2 ownership. Needs the Compose
  owner to emit a separate chroma radius or cap at 12.
- **Mid-frame text gets an opaque cover.** The plan calls for blur + plate;
  the cover guarantees residual old text is gone but is visually a patch.
  The layer warning says to review at 1×.
- **No cancellation for the residual pass.** It renders frames sequentially
  under the request. A 90-minute source should use a short `times` list or
  `max_frames` cap.
- **No Studio UI.** T4 owns `static/studio/check.js` and
  `edit/layers/clean.js`; this track exposes the API and schemas only.
