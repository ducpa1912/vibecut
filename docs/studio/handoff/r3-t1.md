# R3 T1 — Dub and voice workflow

Branch: `rv/r3-t1-dub-voice`
Base: tag `refactor-3-base` = `7e998d1`

## Summary

Dub is no longer a selectable dead end. The Audio panel now detects and confirms the
spoken language, requires a target language, writes `audio.translate = {source, target,
mode}` and keeps any existing translate fields. Dub cannot save without a target, the
save status says so, and an already-broken Dub edit shows a warning plus the target
picker needed to fix it. Voice-over and Dub both have an editable per-line script saved
through the existing `audio_plan.script_overrides` mechanism keyed by scene. Voice is
now the first work card and Music the second. The story queue can show a backend's
failure reason instead of only `Render failed.` The Dub refusal message names the fix.

Translated captions stay deferred, as planned.

- `story_queue.py` — optional `backend.error(item, artifact_id)` hook via `getattr`;

## Known gaps and cross-track integration

1. **`app.py` needs the queue adapter method (T3).** `StoryRenderBackend.error()`
   does not exist yet, so the queue still falls back to `Render failed.` until T3
   adds it. Exact method for T3:
   ```python
   def error(self, item: dict, artifact_id: str) -> str:
       manifest = artifacts.load_manifest(_job_dir(item["job_id"]), artifact_id)
       if manifest is None:
           return ""
       value = manifest.get("error") or manifest.get("message") or ""
       if isinstance(value, dict):
           value = value.get("message") or value.get("detail") or ""
       return str(value or "")
   ```
   The manifest's `error`/`message` is the text `audio.py` raises, e.g.
   `Dub needs a target language. Open Edit > Audio > Dub, choose a target, then save
   before queueing.`
2. **Queue-time Dub preflight belongs to T3/T4.** `finish.js` still queues any saved
   Edit. New Dub edits cannot be saved without a target, but an Edit saved before this
   change can still be queued and will fail at render. With the adapter above, the row
   shows the actionable server reason instead of `Render failed.`. A queue-time
   `dubBlockReason` check in `finish.js` would need that file, which T3 owns.
3. **`edits.py` and the one-line `audio.py` pass-through are outside the strict owned
   list.** They were the smallest way to make the existing `audio_plan.script_overrides`
   field reachable from an Edit without inventing a backend field. If the merge policy
   rejects them, the UI still saves `translate.target`, but script overrides would be
   dropped by `plan_from_edit` and source would 422 at PATCH. Coordinate with the
   audio.py owner before merging.
4. **Translated captions remain deferred.** The UI states that captions stay in the
   source language until Dub renders end to end.
5. **Script keys follow scenes.** One scene that spans several sentences becomes one
   editable line, because `audio.build_script` keys lines by scene and
   `audio_plan.script_overrides` applies one value per scene. Clips without a scene id
   use the story sentence map and the `Sentence <id>` label in `clip.why`; a line with
   no scene at all uses the backend's `"None"` key spelling.
6. **Language list is local and small** (en, es, fr, de, pt, it, ja, ko, zh, hi, ar).
   A saved code outside that list is still shown and saved verbatim.
7. **Source-language detection is a script heuristic**, not the STT report. The picker
   says "Detected from the story" so the creator confirms or corrects it. B's missing
   Chinese transcript is T4's speech work; until that lands, the script box is empty
   for B but the source picker still detects Chinese from the story text.
